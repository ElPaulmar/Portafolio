Postmortalis

Game Designer Writer Documentation

An innovative visual novel about the value of life during the end of the world. The game combines deep narrative decisions with unique autopsy and investigation mechanics.

Summary

  • Context: Postmortalis was developed between February and December 2025 as an experimental visual novel focused on emotional consequences.
  • Premise: The story explores the value of life in a collapsing world through investigations, autopsies and high-stakes dialogue.
  • Approach: Narrative and gameplay systems were iterated in parallel to maintain tone, clarity and player agency.

Team

  • Team size: 6 people in the core development team.
  • Roles involved: Game Design, Programming, Art, Narrative, Audio and QA.
  • Coordination: Regular syncs were used to align narrative goals, gameplay systems and technical milestones.

My Role

  • Game Designer: Designed investigation and autopsy systems tied directly to narrative progression.
  • Writer: Built character arcs, scene logic and branching dialogue structures.
  • Documentation: Produced design docs, balancing tables and flowcharts for team implementation.

Project Goal

The goal of this project was to convey to the player a meaningful end-of-the-world experience. The vertical slice had to be at least 15 minutes long and capable of showing all the key mechanics. To achieve this, we focused on the 2 core systems and on building a mystery story that was compelling but still straightforward to solve.

Design

  • Core Systems: Designed autopsy, investigation and branching dialogue by narrative state.
  • Choice Architecture: Built branching paths with visible consequences on pacing and outcomes.
  • Worldbuilding: Developed a post-apocalyptic context and character motivations tied to gameplay.
  • Narrative Balancing: Tuned chapter rhythm between exposition, conflict and resolution beats.
  • Technical Assets: Organized implementation-ready documentation for cross-discipline collaboration.

PlayMe Studio

Game Designer QA Tester Documentation

490-hour professional internship at a video game development studio. I worked as a Game Designer and QA Tester, contributing to the development and polish of multiple studio projects.

Summary

  • Context: PlayMe Studio was a 490-hour internship completed in 2025 inside a professional game production workflow.
  • Scope: Work combined QA, design support and technical documentation across multiple internal projects.
  • Outcome: The process improved build stability and clarified implementation priorities for production teams.

Team

  • Team size: 8 contributors across design, engineering, art and production.
  • Roles involved: Designers, Developers, Artists, QA and Project Leadership.
  • Coordination: Daily syncs and sprint reviews were used to prioritize fixes and design improvements.

My Role

  • QA Tester: Identified and reported critical issues with reproducible evidence and severity tagging.
  • Game Design Support: Proposed gameplay and flow improvements based on testing outcomes.
  • Documentation: Delivered technical design notes and system specs for implementation alignment.

Project Goal

Since this was a professional internship, my main goal was to learn as much as possible about the industry in a real work environment. I focused on QA tasks and on the core foundations of solid documentation that every designer should know, which helped me integrate professional practices and cross-team communication in multidisciplinary teams.

Design

  • QA Pipeline: Designed a practical bug workflow with severity levels and tracking conventions.
  • Gameplay Review: Evaluated onboarding clarity, feedback loops and progression pacing.
  • Technical Documentation: Created implementation-focused docs for systems, levels and test objectives.
  • Cross-team Iteration: Verified fixes and design changes with development and art teams.
  • Tools: Jira, Confluence, Unity, Google Docs and Slack in daily production use.

Overhaul

Game Designer Writer Narrative Designer

An innovative hack & slash that combines deep narrative with modular combat mechanics. The game features a unique "Downgrades" system where the player progressively loses power, creating a cohesive narrative and mechanical experience.

Summary

  • Context: Overhaul was developed from February to June 2024 as a combat-focused narrative design project.
  • Core Concept: The Downgrades system creates inverse progression where power loss drives both gameplay and story.
  • Production Approach: Fast iterative cycles were used to validate combat readability and narrative cohesion.

Team

  • Team size: 5 people in core production.
  • Roles involved: Game Design, Programming, Art, Animation and QA.
  • Coordination: Weekly reviews aligned narrative milestones with combat system implementation.

My Role

  • Game Designer: Defined combat systems, progression rules and Downgrades logic.
  • Narrative Designer: Wrote story structure, character arcs and dialogue with gameplay consequences.
  • Documentation Lead: Consolidated GDD materials, balancing tables and decision flows.

Project Goal

The team's objective was to create a game with innovative mechanics, good polish, and full compliance with the class rubric requirements. To achieve this, we focused on a strong combat-centered game loop built around the Downgrades mechanic, alongside a narrative that explored player psychology and colonialism.

Design

  • Combat Architecture: Defined weapon styles with different pacing, range and tactical value.
  • Downgrades System: Built inverse progression as both a gameplay and emotional storytelling mechanic.
  • Dialogue Design: Structured branching dialogue with consequences tied to player progression.
  • Balancing: Tuned damage tables and recovery windows for fair challenge under power loss.
  • UX Readability: Improved state feedback for combat clarity and decision-making under pressure.
